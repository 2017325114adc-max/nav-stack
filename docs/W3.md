W3 学习总结：RAII、智能指针与移动语义

1. 什么是对象生命周期？

对象生命周期是指一个对象从创建、初始化、使用到销毁的整个过程。

在 C++ 中，不同存储方式的对象，其生命周期管理方式有所不同。

例如：

int main()
{
    int a = 10;

    return 0;
}

这里的变量 a 是局部对象，在进入其生命周期后可以使用，当程序离开其作用域时，对象生命周期结束。

再看动态分配对象：

int* p = new int(100);

delete p;

这里通过 new 动态分配内存，需要通过 delete 释放对应对象。

如果忘记释放，就可能产生内存泄漏。

在机器人程序中，经常需要创建和销毁传感器数据、图像、点云和算法对象。如果对象生命周期管理不正确，就可能出现内存泄漏、悬空指针和重复释放等问题。

我的理解： 对象生命周期就是对象从产生到销毁的过程。理解对象生命周期，是掌握 C++ 内存管理和资源管理的基础。

2. 构造函数和析构函数有什么区别？

构造函数和析构函数都是类中的特殊成员函数，但它们执行的时机和作用不同。

构造函数

构造函数在对象初始化时自动调用，主要用于初始化成员变量和建立对象所需要的资源。

例如：

class ScopeProbe
{
public:
    explicit ScopeProbe(std::string name)
        : name_(name)
    {
        std::cout << name_ << " constructed\n";
    }

private:
    std::string name_;
};

其中：

explicit ScopeProbe(std::string name)
    : name_(name)

就是构造函数及其成员初始化列表。

析构函数

析构函数在对象生命周期结束时自动调用，主要用于清理对象所管理的资源。

例如：

~ScopeProbe()
{
    std::cout << name_ << " destroyed\n";
}

当对象离开作用域时，析构函数会自动执行。

我的理解： 构造函数负责对象的初始化，析构函数负责对象销毁前的清理工作。两者共同保证对象能够正确地创建和销毁。

3. 什么是 RAII？

RAII 全称是 Resource Acquisition Is Initialization，中文通常称为资源获取即初始化。

它是 C++ 中非常重要的一种资源管理思想。

核心思想是：

将资源的获取和对象的生命周期绑定起来，在对象创建时获取资源，在对象销毁时自动释放资源。

例如：

#include <fstream>

int main()
{
    std::ifstream file("data.csv");

    // 读取文件

    return 0;
}

这里创建 file 对象时，会尝试打开文件。

当 file 离开作用域时，析构函数会自动关闭文件。

不需要手动调用文件关闭操作。

RAII 不仅可以管理文件，还可以管理：

动态分配的内存。

互斥锁。

网络连接。

其他需要申请和释放的资源。

在机器人算法开发中，RAII 可以帮助管理图像缓冲区、传感器数据、动态内存和线程锁等资源。

我的理解： RAII 的核心是让资源跟随对象的生命周期进行管理，尽可能避免手动申请资源后忘记释放的问题，提高程序的稳定性和可靠性。

4. 什么是 unique_ptr？

std::unique_ptr 是 C++ 标准库提供的一种智能指针，用于独占管理动态分配的对象。

例如：

#include <iostream>
#include <memory>

int main()
{
    std::unique_ptr<int> p =
        std::make_unique<int>(100);

    std::cout << *p << std::endl;

    return 0;
}

这里：

std::unique_ptr<int>

表示一个独占管理 int 对象的智能指针。

而：

std::make_unique<int>(100)

负责创建对象，并将其所有权交给智能指针。

当 p 离开作用域时，它会自动释放所管理的对象。

因此不需要手动调用 delete。

unique_ptr 的特点

具有独占所有权，同一时刻只能有一个 unique_ptr 拥有该资源。

不允许直接复制。

可以通过移动语义转移资源所有权。

离开作用域时自动释放所管理的资源。

我的理解： unique_ptr 是一种能够自动管理动态内存的智能指针，它通过独占所有权避免多个对象同时管理同一块资源，减少内存泄漏和重复释放的问题。

5. 为什么不能复制 unique_ptr？

因为 unique_ptr 的设计原则是独占所有权。

例如：

auto p1 = std::make_unique<int>(100);

auto p2 = p1;

上述代码无法编译。

原因是，如果允许直接复制，那么 p1 和 p2 就可能同时拥有同一个动态对象。

假设两个指针都认为自己拥有这块内存，当它们分别销毁时，就可能对同一块内存重复释放。

这会造成严重的内存管理问题。

因此，unique_ptr 删除了拷贝构造函数和拷贝赋值运算符。

如果希望将资源交给另一个 unique_ptr 管理，需要使用移动语义：

auto p1 = std::make_unique<int>(100);

auto p2 = std::move(p1);

执行之后：

p2 接管原来由 p1 管理的资源。

p1 不再拥有这个对象，通常变为空指针。

原来的对象只由 p2 管理。

我的理解： unique_ptr 不能复制，是为了保证同一份资源只有一个明确的所有者。需要改变所有权时，可以使用移动语义，而不是复制指针。

6. 什么是移动语义？

移动语义是 C++11 引入的一种资源管理机制。

它允许对象在特定情况下转移内部资源的所有权，而不必复制整个资源。

例如，一个 ImuBuffer 管理了一块包含大量 IMU 数据的动态数组。

如果复制它，就可能需要重新申请内存，并把所有数据逐个复制过去。

而移动语义可以直接转移动态数组的所有权，避免不必要的数据复制。

例如：

ImuBuffer source(3);

ImuBuffer destination(std::move(source));

这里通过移动构造函数，将 source 管理的资源转移给 destination。

移动完成后：

destination 拥有原来 source 的数据。

source 不再拥有原来的数据。

source 仍然是一个可以安全销毁或重新赋值的对象。

在我的 ImuBuffer 实现中，移动后主动将源对象的 size 和 capacity 设置为 0，使它处于有效的空状态。

我的理解： 移动语义不是简单地复制对象，而是转移对象内部资源的所有权，可以减少不必要的数据复制，提高程序处理大型数据和管理动态资源的效率。

7. std::move 的作用是什么？

std::move 是 C++ 标准库提供的一个类型转换工具。

它的主要作用是将对象转换为右值引用形式，使编译器能够选择移动构造函数或移动赋值运算符。

例如：

auto p1 = std::make_unique<int>(100);

auto p2 = std::move(p1);

这里：

std::move(p1)

让 p1 可以参与移动操作。

需要特别注意：

std::move 本身并不会直接搬运数据或转移资源。

它主要负责类型转换，真正的资源转移由对应的移动构造函数或移动赋值运算符完成。

在 unique_ptr 中，标准库已经实现了相应的移动操作，因此可以直接使用 std::move。

在自己编写的 ImuBuffer 中，也需要实现移动构造函数和移动赋值运算符，才能完成资源转移。

我的理解： std::move 本身不负责搬运资源，而是将对象转换成适合移动操作的右值引用形式，让对应的移动构造或移动赋值函数能够接管资源。

8. 移动构造和移动赋值有什么区别？

两者都用于转移对象的资源所有权，但调用时机不同。

移动构造

移动构造是在创建一个新对象时，通过一个右值引用对象初始化新对象。

例如：

ImuBuffer source(3);

ImuBuffer destination(std::move(source));

这里 destination 原本不存在，因此需要通过移动构造函数创建它。

移动构造函数：

ImuBuffer(ImuBuffer&& other) noexcept
    : data_(std::move(other.data_)),
      capacity_(other.capacity_),
      size_(other.size_)
{
    other.capacity_ = 0;
    other.size_ = 0;
}

它将 other 管理的资源转移给新创建的 destination。

移动赋值

移动赋值是在一个已经存在的对象上进行资源替换。

例如：

ImuBuffer source(3);

ImuBuffer destination(10);

destination = std::move(source);

这里 destination 已经创建，因此不需要重新构造对象，而是通过移动赋值运算符替换它原有的资源。

移动赋值函数：

ImuBuffer& operator=(ImuBuffer&& other) noexcept
{
    if (this != &other)
    {
        data_ = std::move(other.data_);

        capacity_ = other.capacity_;

        size_ = other.size_;

        other.capacity_ = 0;

        other.size_ = 0;
    }

    return *this;
}

其中，unique_ptr 在接管新资源时，会自动释放 destination 原先管理的动态数组。

我的理解： 移动构造是在创建新对象时转移资源，移动赋值是在已经存在的对象之间转移资源。两者都可以避免不必要的数据复制，但是使用场景不同。

9. unique_ptr 和 shared_ptr 有什么区别？

本周主要学习了 unique_ptr，shared_ptr 只了解了基本概念。

两者的主要区别在于资源所有权。

unique_ptr

独占所有权，同一时刻只能由一个 unique_ptr 管理对应资源。

shared_ptr

共享所有权，允许多个 shared_ptr 共同管理同一个对象，通过引用计数跟踪共享所有者。

例如：

auto p1 = std::make_shared<int>(100);

auto p2 = p1;

此时 p1 和 p2 共同管理同一个对象。

当最后一个拥有该对象的 shared_ptr 销毁时，资源才会被释放。

两者的选择应该根据实际资源所有权关系决定。

一般情况下，优先使用 unique_ptr；只有确实需要共享所有权时，再考虑 shared_ptr。

本周还学习了两个重要的工程调试工具。

GDB

GDB 是 GNU Debugger，用于调试 C++ 程序。

可以通过断点、单步执行、查看变量和函数调用栈等方式观察程序运行过程。

本周通过 GDB 调试 ImuBuffer，重点观察移动构造函数是否正确执行，以及移动前后对象的状态变化。

Valgrind

Valgrind 是一套程序分析工具，本周主要使用它检查动态内存管理问题。

例如：

valgrind --leak-check=full \
./build/imu_buffer_demo

重点关注：

definitely lost：明确丢失的内存。

indirectly lost：由于其他丢失对象而无法访问的内存。

possibly lost：可能丢失的内存。

still reachable：程序结束时仍然可以访问的内存。

其中，definitely lost 是重点关注的明确内存泄漏类别。

另外，本周还初步使用了 AddressSanitizer 和 UndefinedBehaviorSanitizer，帮助检查非法内存访问和未定义行为。

我的理解： GDB 主要帮助我们观察和调试程序执行过程，Valgrind 主要帮助我们分析内存使用和泄漏问题，ASan/UBSan 则能够检测多种内存访问错误和未定义行为。这些工具能够帮助定位 C++ 工程中的问题。
